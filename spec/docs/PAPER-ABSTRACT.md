# Specification-Governed Software Engineering: Process Algebra as a Semantic Anchor for LLM-Assisted Development

## Abstract

Large language model coding agents demonstrate high syntactic fluency but systematic semantic shallowness: they operate on code structure rather than behavioural intent, making them unreliable for tasks requiring comprehension of implicit runtime dependencies. This paper presents Specification-Governed Software Engineering (SGSE), a methodology that addresses this limitation by specifying a system as a network of agents, each visible only through named, typed ports. The set of ports and their value types constitutes the system's entire contract — to its users and to its other components alike. Because every dependency is a declared port rather than an implicit relationship, the step at which unconstrained agents characteristically fail — inferring hidden dependencies from code — is removed by construction.

We adopt value-passing CCS as the specification language, chosen for its interaction-centric abstraction, explicit dependency representation through typed port synchronisations, symmetric treatment of user and system processes, and — critically — its guarding mechanism, which yields state-dependent port availability as a native semantic feature. The methodology defines three levels: a formal port-signature specification in process algebra (L1), an abstract interaction-form vocabulary mapping each port to a presentation (L2), and a framework-specific skin (L3). L2 and L3 together constitute a swappable presentation artefact; the contract beneath them is untouched by skin changes.

A central contribution is the separation of an agent's static interface (its *sort*, the full port alphabet) from its dynamic interface (its *ready set*, the ports offered in the current state, fixed by guarding). It follows that control enablement is derived from the specification rather than invented in the UI layer: a skin renders the ready set; it does not decide it. This dissolves the familiar bug class of ad-hoc enable/disable logic drifting out of step with the model. We further show that read-only state displays need not breach encapsulation: a display is an output-only port carrying a projection the agent chooses to publish, keeping the principle that data crosses only at ports intact.

We validate the approach through a worked example migrating a multi-component Python pronunciation-training application (miolingo) from Streamlit to PyQt, executing the CCS specification on an existing Wolfram-based CCS engine to confirm behaviour independently of any presentation framework. We identify a framework selection criterion with a concrete, falsifiable form: a view port that emits on state-change *is* a Qt signal, and a ready set *is* a set of enabled connections, whereas Streamlit's whole-script rerun only simulates both — so Qt's compatibility advantage rests on native constructs, not aesthetics. We additionally identify a genuine boundary case: CCS synchronisation is a blocking rendezvous, yet proactive enablement rendering requires the ready set without a sync, demanding a non-blocking introspection the bare calculus does not provide. We locate this as an obligation on each agent encoding, which must compute its currently afforded ports on the fly from live state, and treat conformance to `init(P)` as a verification target.

The methodology yields CCS-derived test processes as a principled replacement for GUI-level integration tests. Because the current ready set coincides with the ready/refusal set of testing-and-failures semantics, verifying a skin against the specification reduces to checking ready-set agreement at each reachable state — testing equivalence rather than trace inclusion alone — independently of any presentation framework. This resolves the integration-testing problem that arises when migrating away from web systems with mature browser-automation tooling.

We conclude that formal specification need not impede agile development when agents handle implementation mechanics, and that process algebra offers a practical, theoretically grounded foundation for human–agent collaborative software engineering. The human role shifts from writing code to governing behaviour — authoring port-signature specifications, choosing interaction forms, and reviewing ready-set and trace behaviour — while agents execute bounded, verifiable rendering tasks under formal constraint. We note where the model stops short: spatial and nesting relationships are deliberately left to the presentation layers, and the place-structure of bigraphs is reserved for a future multi-user variant in which locality becomes semantically load-bearing.

## Keywords

process algebra, CCS, value-passing, LLM agents, software specification, agentic software engineering, UI framework migration, formal methods, testing equivalence, PyQt, human–agent collaboration

## Status Note

This abstract is written prospectively. The conceptual architecture — the port-signature contract, the sort/ready-set distinction, read-only views as projections, and the bigraph deferral — is established. Empirical validation, comprising the Streamlit/Qt comparative study, the framework-selection-criterion evaluation, the ready-set lookahead design, and the test-process substitution experiment, constitutes the research programme ahead.
